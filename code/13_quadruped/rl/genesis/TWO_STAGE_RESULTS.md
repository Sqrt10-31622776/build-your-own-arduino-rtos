# 2 段モデル: 段 B の有無の比較結果

`joint` (段 A + 関節ごとの残差 段 B) と `baseline` (段 B なし、段 A 単体) を、同じ環境・同じ報酬・同じ学習量で学習して比べた結果です。
実装は [TWO_STAGE.md](TWO_STAGE.md)、実行は `compare_two_stage.sh` です。
**最新の結論は 1 節で、各モード 7 seed を 9200 iteration 相当まで学習した結果です (第 4 回)。** 途中の結果として、2300 iteration (第 1 回)、4600 iteration の 3 seed (第 2 回)、6 seed (第 3 回) を 1.1〜1.3 節と 4.5〜4.9 節に残しています。結論は、学習量を増やすたびに変わったので (第 1 回 → 第 2 回で `baseline` の失敗が解消、第 3 回で seed 6 が失敗、第 4 回で解消)、古い節の結論をそのまま読まないでください。

## 1. 結論 (9200 iteration、各モード 7 seed)

以下が最新の結論です。1.1〜1.3 節は、そこに至る途中の結果 (4600 iteration 時点の 3 seed と 6 seed、baseline seed 6 の延長) で、当時の結論の一部は、この節で置き換わっています。

seed 1〜6 の全 run を、最終チェックポイントから `--resume` で 9200 iteration まで延長し (`run_extend.sh` / `run_extend2.sh`、8192 env)、さらに seed 7 を各モード 9200 iteration で最初から通しで学習しました (`run_queue.sh`)。これで各モード 7 seed、すべて 9200 iteration 相当です (seed 1〜3 は 3 区間、seed 4〜6 は 2 区間に分けた学習、seed 7 だけ 1 区間)。評価は `sim2sim.py --sim genesis`、DR なし/あり × 4 コマンド (1 モードあたり 7 seed × 8 = 56 条件)、集計は `analyze_two_stage.py` です。

seed ごとの最終報酬 (seed 1〜7): `joint` は 90.3 / 66.0 / 89.1 / 85.8 / 87.4 / 87.7 / 63.8、`baseline` は 74.4 / 71.4 / 85.6 / 80.3 / 72.7 / 76.7 / 84.6 です。

1. **9200 iteration まで学習すると、`baseline` も 7 seed すべてで離陸し、評価は全 56 条件で転倒ゼロになりました。** 1.2 節の seed 6 の失敗は、学習量の不足によるものでした。
2. **最終報酬の差は小さく、有意とは言えません** (p = 0.21、81.4 ± 10.6 と 78.0 ± 5.3)。`joint` のほうがばらつきが大きく、離陸が遅かった seed 2 と seed 7 は、最終報酬も 66.0 と 63.8 で全 14 run の中で最も低い部類です。`baseline` の最低は 71.4 です。
3. **離陸の速さの差は、7 seed でも残っています** (中央値 785 と 2729 iteration、p = 0.038、下の 6.)。ただし `joint` にも遅い seed (seed 2: 2043、seed 7: 2646) があり、`baseline` の seed 2 は 494 で早く離陸しました。分布は重なっています。
4. **評価の追従は、並進が同等になりました** (0.0039 と 0.0037 m/s)。1.2 節の 0.0043 と 0.0081 の差は、`baseline` の seed 6 の転倒を除いた条件の偏りと、学習量の不足によるものと考えられます。旋回 (0.084 と 0.108 rad/s) と roll は `joint` がやや良好ですが、差は小さく、seed 間のばらつきの範囲です。
5. **4600 iteration を境に、報酬が一時的に 5〜10 下がる seed が多くあります** (seed 1〜6 の再開直後、200 iteration 平均で `joint` seed 1: 83 → 76 など)。通しで学習した seed 7 には、この低下がありません。`--resume` に伴うものと見られますが、原因は調べていません。報酬は、その後すぐ回復しています。
6. **離陸の速さの差は、7 seed ずつの Mann–Whitney U 検定 (両側) で p = 0.038 でした。** 最終報酬 (p = 0.21)、DR なしの旋回指令 0.3 rad/s の実測 wz (p = 0.20) には、有意な差がありません。検定は 1 回の探索的な比較で、多重比較の補正はしていません。
7. 学習曲線 (200 iteration ごとの平均) は `two_stage_reward_curves.png` です。

## 1.1 途中経過: 3 seed、4600 iteration (第 2 回)

| 指標 | joint (A+B) | baseline (A のみ) |
|---|---|---|
| 最終平均報酬 (最後の 100 iteration、3 seed の平均 ± 標準偏差) | 78.7 ± 12.6 | 71.5 ± 8.2 |
| エピソード長が上限 (1000) 近くに達した seed | 3 / 3 | 3 / 3 |
| 評価で全ロボットが転倒した条件 (3 seed × 4 コマンド × DR なし/あり = 24) | 0 / 24 | 0 / 24 |
| 評価の並進誤差 \|vx − 指令\| (m/s) | **0.0043** | 0.0098 |
| 評価の旋回誤差 \|wz − 指令\| (rad/s) | **0.086** | 0.122 |
| 報酬の移動平均が初めて 20 を超えた iteration (3 seed / 中央値) | **462 / 785 / 2043 (785)** | 494 / 2729 / 3874 (2729) |

> この節の結論 1〜2 は、seed を増やした 1.2 節で、`baseline` の seed 6 が 4600 iteration で離陸せず覆り、さらに 9200 iteration まで学習した 1 節で、再び成り立つようになりました。

1. **十分に長く学習すれば、`baseline` (段 B なし) も、`joint` と同じように歩けるようになります。** 4600 iteration で、両モードとも 3 seed すべてで、エピソード長が 991〜1000、評価の 24 条件すべてで転倒ゼロでした。
2. **最終的な報酬に、明確な差はありません。** 78.7 ± 12.6 と 71.5 ± 8.2 で、差 (7.2) は標準偏差と同程度か小さく、3 seed では有意とは言えません。
3. **離陸 (報酬が上がり始める時点) は、`joint` のほうが早い傾向があります。** 報酬の移動平均が 20 を超えた iteration の中央値は、`joint` が 785、`baseline` が 2729 です。`baseline` の seed 1 と 3 は、2300 iteration まで報酬 1 前後で停滞し、それぞれ 2729 と 3874 iteration でようやく離陸しました。ただし `joint` の seed 2 も、離陸に 2043 iteration かかっており、3 seed で見た傾向です。
4. **評価の追従は、`joint` がわずかに良好です** (並進誤差 0.0043 vs 0.0098 m/s、旋回誤差 0.086 vs 0.122 rad/s)。ただし、旋回の実測は seed によるばらつきが大きく (4.9 節)、この差を段 B の効果と断定できません。
5. **旋回は、どちらのモードでも指令の半分以下です** (指令 0.3 rad/s に対して、実測の平均は `joint` が 0.128、`baseline` が 0.082)。

**第 1 回 (2300 iteration) との違い**: 第 1 回では、`joint` が 24 条件で転倒ゼロ、`baseline` が 12 / 24 条件で全転倒でした (4.7 節)。この差は、`baseline` の seed 1 と 3 の学習が、まだ離陸していなかったためで、モデルの能力の差ではありませんでした。

## 5. 考察

数字は 1 節と 4.1〜4.4 から引いています。

1. **学習の成否** (4.1)
   - 9200 iteration で、両モードとも 7 本すべてが離陸し、エピソード長は 997〜1000 に達しました。評価は 112 条件 (各モード 56) すべてで転倒ゼロです。
   - 4600 iteration で離陸していなかった `baseline` の seed 6 は、5128 iteration で離陸し、76.7 まで上がりました。`baseline` の seed 1・3・4・5・6・7 は、2300 iteration の時点で報酬が 6 以下 (多くは 1 前後) で、その後に離陸しており、長い停滞は「学習できない」ことを意味しません。ただし、停滞が長引くほど、必要な学習量は増えます。
2. **最終的な報酬** (4.1)
   - `joint` は 81.4 ± 10.6、`baseline` は 78.0 ± 5.3 で、有意な差はありません (Mann–Whitney p = 0.21)。
   - `joint` の seed は 2 群に分かれます。離陸が早かった 5 seed は 85.8〜90.3 で、`baseline` の最高 (85.6) と同程度以上です。離陸が遅かった seed 2 と seed 7 は 66.0 と 63.8 で、全 14 run の最低です。`baseline` は 71.4〜85.6 の間に散らばっています。
   - `baseline` の seed 1 は、後半に報酬が下がっています (200 iteration 平均で 83 → 74)。`baseline` の seed 2・5・6 と `joint` の seed 6 は、9200 iteration の時点でも上昇が続いています。最終報酬は、学習量で変わります。
3. **離陸の早さ** (4.1)
   - 報酬の移動平均が 20 を超えた iteration の中央値は、`joint` が 785、`baseline` が 2729 で、7 seed ずつの比較で有意な差があります (p = 0.038)。
   - ただし分布は重なっています。`joint` の seed 2 (2043) と seed 7 (2646) は、`baseline` の seed 2 (494) より遅く、`baseline` の seed 4・7 (2408、2560) と同程度です。
   - 段 B の効果は、学習の「成否」ではなく「速さ」にあると言えます。ただし、離陸の速さが最終的な性能に結びつくわけではなく、`joint` で最も遅く離陸した 2 seed は、最終報酬も低いままです。
4. **評価での並進追従** (4.2, 4.3)
   - `joint` が 0.0039 m/s、`baseline` が 0.0037 m/s で、同等です。4600 iteration の 0.0043 と 0.0098 (3 seed) や 0.0043 と 0.0081 (6 seed) にあった差は、`baseline` の学習量不足の影響でした。
5. **旋回追従** (4.3, 4.4)
   - 指令 0.3 rad/s に対して、実測 wz は `joint` が平均 +0.141、`baseline` が +0.097 で、どちらも指令の半分未満です。2 モードの差は有意ではありません (DR なしの seed ごとの値で p = 0.20)。
   - seed によるばらつきが大きく、`joint` は +0.073〜+0.246、`baseline` は +0.044〜+0.166 です。
   - **報酬が高いことと、旋回追従の良さは一致していません。** `joint` で旋回が最もよい seed 2 (+0.246) と seed 7 (+0.229) は、最終報酬が最も低い 2 seed です。報酬が最も高い seed 1 (90.3) の旋回は +0.073 です。この傾向は、4600 iteration の 3 seed (seed 2 が旋回最良) でも見られました。報酬に旋回の追従が十分に効いていない可能性がありますが、報酬の内訳は確認していません。
6. **姿勢と歩容** (4.2, 4.3)
   - roll RMS は全条件で、`joint` が 1.84°、`baseline` が 2.37° で、`baseline` のほうがやや大きいです。pitch RMS は同等です (3.97° と 3.90°)。
   - コマンド別では、`joint` の roll は 1.1〜3.0°、`baseline` は 1.4〜3.3° です。
7. **`joint` の seed 2 と 7 は、ほかの run と歩き方が違います** (付録 C、学習ログの報酬の内訳、動画 `videos/joint_s1.mp4` と `videos/joint_s2.mp4`)。
   - 評価 (指令 0.06,0・DR なし) では、4 本の足の接地率がほぼ同じ 0.19〜0.25 に揃っています。合計が 1 を下回るので、全脚が浮く時間がある、跳ねるような歩き方です。足の持ち上げは 13.3〜13.4 mm、接地中の滑りは 46.5〜46.7 mm/s で、ほかの 12 run (4.0〜7.4 mm、9.1〜28.7 mm/s) の 2〜3 倍です。
   - 学習ログの最後の報酬の内訳でも、この 2 seed だけが外れています。`track_lin_vel_filtered` は 2.64 / 2.66 (ほかの `joint` は 3.34〜3.47)、`feet_air_time` は 0.015 / 0.014 (同 0.065〜0.077)、`feet_swing_height` のペナルティは −0.53 / −0.55 (同 −0.88〜−0.98) です。
   - seed 1 と seed 2 の動画を見比べて、上の違い (seed 2 は跳ねるように歩く) を確認しました。
   - 離陸が遅く、行動の標準偏差も大きい (0.072・0.077、ほかの `joint` は 0.037〜0.041) ことと対応しています。旋回が最もよいのも、この 2 seed です (5. の 3 つ目の点)。
   - `baseline` には、この歩き方に入った run はありません。ただし seed 2・5 は、足の高さと滑りが少し大きめで、行動の標準偏差も中間です (0.056〜0.058)。
   - この歩き方に入る原因、局所解かどうかは、確かめていません (6 節)。
8. **再開に伴う報酬の低下** (1 節の 5.)
   - seed 1〜6 は、4600 iteration 付近の `--resume` の直後に、200 iteration 平均の報酬が 5〜10 下がり、すぐ戻っています。通しで学習した seed 7 には見られません。`--resume` では、モデルとコマンドカリキュラムを復元しますが、他の学習状態 (オプティマイザの状態など) が復元されているかは確認していません。
   - 報酬の曲線にこの落ち込みが入るので、seed 1〜6 と seed 7 を、学習の曲線の形で直接比べるときは注意が必要です。最終値への影響は、見られません。

## 6. 制限と、まだ分かっていないこと

- **seed 数は各 7 です。** 離陸の速さの差は p = 0.038 ですが、これは 1 つの指標についての探索的な検定で、多重比較の補正をしていません。最終報酬と旋回追従の差は、7 seed では検出できませんでした。差がないとも言えません。確かめるには、seed を増やす (例 各 10 以上) 必要があります。
- **学習量は 9200 iteration で打ち切りました。まだ収束しきっていない run があります。** `baseline` の seed 2・5・6 と `joint` の seed 6 は、末尾でも報酬が上昇しています。逆に `baseline` の seed 1 は、後半に下がっています。さらに回すと、最終報酬の比較は変わる可能性があります。
- **seed 1〜6 と seed 7 で、学習の区切りが違います。** seed 1〜3 は 3 区間、seed 4〜6 は 2 区間、seed 7 は 1 区間です。再開の直後に報酬が下がる現象 (5 節 7.) があり、`--resume` が最終的な性能に影響していないことは、確認していません。
- **`joint` の seed 2 と 7 が、別の歩き方 (跳ねるような歩き方) に入った原因は、確かめていません。** 局所解かどうかも不明です。9200 iteration でも報酬が平らなだけで、さらに学習すれば抜ける可能性があります。確かめるには、この 2 seed の延長、同じ seed での `init_std` や報酬の重みの変更、seed 数の追加が必要です。
- **旋回の追従が弱い原因は特定していません。** 報酬のバランス、学習量、遅延 0 の環境の影響などが考えられます。
- **学習の失敗や停滞が、モデルの構造のせいか、ハイパーパラメータ (`init_std`=1.0、学習率、KL 目標など) のせいかは切り分けていません。** 両モードで同じ値を使っています。
- **比較したのは「段 B の有無」だけです。** 従来の方策 (遅延 4〜7、3 フレーム履歴の現行モデル) との比較、`frozen` (既存方策への後付け) の効果は未検証です。
- 評価は 1 つの評価 seed (0) と 4 コマンドです。旋回の指令の大きさを変えた評価、後退や他の指令の組み合わせの評価はしていません。
- **学習は、ローカルとリモートの 2 台で行っています。** 速度は同程度ですが、浮動小数点の結果が完全に同じとは限りません。
- 実機の遅れ (サーボ内部約 23 ms) は、この sim では遅延 0 にしています。実機への適用性は、この結果からは言えません。

## 7. 再現

2 台目の GPU マシンは環境変数で指定します (`REMOTE`: ssh のホスト、`REMOTE_DIR`: そのホスト上の `rl/genesis`、`REMOTE_PY`: そこで使う python)。

```
export REMOTE=<ホスト> REMOTE_DIR=<rl/genesis のパス> REMOTE_PY=<python のパス>
sh compare_two_stage.sh            # 第 1 回: 6 本の学習 (2300 iteration) と評価、2 台の GPU
sh compare_two_stage.sh extend     # 第 2 回: 全 6 本を +2300 iteration 延長 (--resume) して再評価
sh compare_two_stage.sh status
sh compare_two_stage.sh fetch      # リモートの results/logs を取り込む
sh run_queue.sh 8192 4600 joint:4 baseline:4          # seed 4〜6: 4600 iteration を通しで学習 (seed 7 は 9200)
PY=<python> sh run_extend.sh 8192 2300 baseline:1     # 1 回目の延長 (元の run の最終チェックポイントから)
PY=<python> sh run_extend2.sh 8192 4600 baseline:1:baseline_s1_ext:baseline_s1_ext2   # 延長した run の続き
.venv/bin/python analyze_two_stage.py      # 集計 (報酬・離陸・評価)
.venv/bin/python make_9200_tables.py       # 4 節・付録 C の表
.venv/bin/python plot_two_stage_curves.py  # 報酬曲線
```

- 生データ: `results/<mode>_s<seed>.txt` (最初の run の評価)、`_ext.txt`、`_ext2.txt` (延長後の評価。9200 iteration の評価は、各 seed の最後のもの)、`.train.log` (学習ログ)。
- チェックポイント・tensorboard: `logs/rsl_rl/arduino_quad_velocity/*_<mode>_s<seed>[_ext|_ext2]/`。
