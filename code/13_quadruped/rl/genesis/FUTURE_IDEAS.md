# 2 段モデルの今後のアイデア

[TWO_STAGE.md](TWO_STAGE.md) (実装) と [TWO_STAGE_RESULTS.md](TWO_STAGE_RESULTS.md) (段 B の有無の比較結果) を踏まえた、次にやること・試せることの整理です。いずれも**未実施の案**で、効果は検証していません。

## 0. 目的と現状

**目的**: 全体の計算 (段 A) には時間がかかり、リアルタイムのデータが使えない。計算のあとにローカルで小さい補正 (段 B) をすれば、より新しいデータを使えるのではないか。

**現状の結果** (4600 iteration、各 3 seed):

- 最終報酬は `joint` 78.7 ± 12.6、`baseline` 71.5 ± 8.2 で、有意な差はない。
- `joint` のほうが離陸が早い傾向 (報酬の移動平均が 20 を超えた iteration の中央値 785 vs 2729)。
- 評価の追従誤差は `joint` がわずかに良い (並進 0.0043 vs 0.0098 m/s)。
- 旋回は両モードとも指令 (0.3 rad/s) の半分以下。

**今の比較が目的の検証になっていない理由**:

| | 目的が想定する状況 | 今の実験 |
|---|---|---|
| A の遅れ | 大きい (重い計算) | 1 フレーム = 20 ms だけ |
| B が見る新しい情報 | A が持っていない新しい状態 | s_t 1 枚だけ (A との差が小さい) |
| 評価 | 状況が変わる (外乱など) | 外乱なしの定常歩行 |

この条件では B が足せる情報がほぼなく、最終報酬に差がないのは自然です。「B が無意味」とは言えません。

## 1. 各モードの作りと意図

```
single ── (環境を遅延0・4フレーム履歴に変える) ──> baseline  ← 「段Bなし」の対照
                                                      │ 段Bを足す
                                                      ▼
                                      joint (A+Bを同時に学習)
                                      frozen (学習済みAに、Bだけ後付け)
```

| モード | 作り | 意図 |
|---|---|---|
| `single` | 87→96→64→8 の MLP 1 本。サーボ遅延 4〜7 サブステップ | 従来の方策。比較の基準点で、実機に載せられる (JIT/ONNX 対応) のも現状これだけ |
| `baseline` | `single` と同じ形。環境は遅延 0、4 フレーム履歴の先頭 3 フレームを入力 | 段 B の効果を切り分ける対照。`joint` との差は「s_t を見る段 B の有無」だけ |
| `joint` | 段 A + 関節ごとの段 B (10→16→16→1 を 8 個、残差)。A と B を同時に PPO で学習。B の最終層はゼロ初期化 | 「重い A は少し前の状態、軽い B は直前の s_t」という 2 段の時間構造そのものを学ばせる本命 |
| `frozen` | 学習済みの A を凍結し、B だけ学習 (`init_std` 0.2) | 既存の方策に後付けで補正を足す使い方 (目的に最も近い)。A が同一なので B の効果だけを切り分けて測れる |

`frozen` の価値:

1. **比較の公平性**: A が同一なので、同じ A に B を付ける前後で比べられる。`joint` の seed 間ばらつき (離陸が 462〜2043 iteration) の影響を受けない。
2. **目的への対応**: 重い A を作り直さず、軽い B (3.7k パラメータ) だけ追加できる。
3. **学習の安定**: B の最終層がゼロ初期化なので、開始時は a = â (A 単体と同じ性能)。A が歩けるので探索ノイズも小さくできる。

注意: `frozen` は未検証。さらに、A を学習した環境 (`single`: 遅延 4〜7) と `frozen` の環境 (遅延 0、4 フレーム履歴) が違う。公平に検証するには、A を学んだ環境と B の環境を揃える必要がある。

## 2. 背景知識 (機械学習の用語)

- **強化学習 (PPO)**: ロボットを動かして得た報酬から、良い行動を強める試行錯誤の学習。正解を教えてもらえないので遅く不安定で、長い停滞 (報酬 1 前後) も起きる。
- **教師あり学習**: 「入力 → 正解」の対応を学ぶ。正解が用意できれば、強化学習よりずっと速く安定する。
- **探索ノイズ (標準偏差 σ)**: PPO の方策はガウス分布 (平均 a、標準偏差 σ) から行動をサンプルする。σ が大きいと探索は広いが動きは荒れ、小さいと安定するが新しい動きを見つけにくい。`init_std` はその初期値 (ゼロから学ぶなら 1.0、歩ける A がある `frozen` は 0.2)。
- **学習率**: 1 回の更新でパラメータを動かす大きさ。大きいと速いが壊れやすい。
- **模倣学習・蒸留**: うまい先生の動きを、生徒に回帰で真似させる。蒸留は、特権的・大きい先生から、制限された・小さい生徒へ能力を移すこと。
- **特権情報**: 学習中 (sim) だけ使え、実機では取れない情報 (現在の Critic の入力など)。先生に持たせ、生徒は実機で取れる情報だけで動かす、という使い方がよくある。
- **補助タスク**: 本来の目的とは別の問題を同じネットワークに解かせ、内部表現を良くする方法。

## 3. 提案

優先順位は A → B-3/B-4 → B-1/C-3 → C-2 です。A は B・C の効果を確かめる前提になります。

### A. 実験条件を目的に合わせる (最優先、低コスト)

**意図**: 「段 B が役に立つ状況で比べないと、役に立つかどうかは分からない」。B が足せる情報量は「A の遅れ」と「予想外の出来事」で決まるので、その両方を実験に入れる。ここで B の効果が確認できなければ、B・C の改良は効果のないものを磨くことになる。逆に効果が見えれば、どの改良が効くかも判断しやすくなる。

| 案 | やること | 意図 | 見るもの |
|---|---|---|---|
| A-1 | A の遅れ N を 1, 2, 3, 5 フレームに変え、各 N で `joint` と `baseline` を比べる | 「遅れが大きいほど B の価値が上がる」を直接検証する | 横軸 N、縦軸 報酬 (追従誤差) で 2 本の差が開くか |
| A-2 | 評価中にロボットを押す外乱評価を足す | 外乱は A の予想を外す出来事で、B が最新の状態で補正する価値が最も表れる | 同じ力で押したときの転倒率と回復時間 |
| A-3 | 遅れのある環境で学習した A に、`frozen` で B だけ後付けして学ぶ | A が同一なので B の効果だけを測れる。動機 (既存方策への後付け) にも直結 | 後付け前後の報酬・外乱耐性 |

実装上は、遅れは `--delay-min/--delay-max` で変えられ、`frozen` も実装済み。追加が要るのは外乱評価と実験スクリプトくらい。A-3 は A の学習環境と B の環境の遅れを揃えること。

### B. 学習方法

| 案 | 内容 | 狙い | 注意 |
|---|---|---|---|
| B-1 教師あり蒸留 | 遅れなしで s_t を見て歩ける特権教師を別に学び、Δ* = a_teacher(s_t) − â(s_{t-1}) を正解に B を回帰で学ぶ。生徒 (A+B) を実際に動かした状態でラベルを取り直す (DAgger 風) と、ずれが雪だるま式に広がるのを防げる | PPO より B の学習が速く安定。`baseline` のような長い停滞を避ける | 先生を先に作る手間。B は先生以上にならない (最後に PPO で微調整する余地はある) |
| B-2 補助予測 | A が行動 â に加えて次の状態 ŝ_t も予測し、B には予測誤差 (s_t − ŝ_t) を入力する | 予想外のこと (外乱・滑り) が起きたときだけ B が反応する構造になる。予測は「実際の次の状態」が正解なので教師あり学習でき、学習信号が密 | 観測ノイズ (`joint_pos` ±0.02 など) と本当の外乱を区別できるか。損失の重みの調整 |
| B-3 段階学習 | ① A だけ学習 → ② A を凍結して B を学習 (`frozen`) → ③ 低い学習率で A+B を微調整 | `joint` で A と B を同時にゼロから学ぶことによる離陸のばらつき (462〜2043 iteration) の解消 | ③ の学習率が大きいと固めた A が崩れる。① は遅れのある環境で学ぶのが望ましい |
| B-4 ノイズ分離 | B 側だけ σ を小さくする、または出力に上限 (tanh × スケール、例 ±0.1 rad) を付ける | 小さな補正がノイズに埋もれず、B が暴れない | 上限が小さすぎると必要な補正が出せない。先に Δ の実際の大きさを測って決める |

### C. モデルの作り方

| 案 | 内容 | 狙い | 注意 |
|---|---|---|---|
| C-1 PD 構造 | Δ_j = Kp_j·(â_j − q_j) + Kd_j·(−q̇_j) + 小さい MLP。Kp, Kd は関節ごとの学習パラメータ (0 付近から開始) | 「A の目標に、直前の状態で追従を速める」という B の役割が構造に現れる。学習後にゲインを見れば説明できる (解釈性) | サーボ側にも PD があり二重に効きすぎるので、ゲインに上限を付ける |
| C-2 action chunking | A が未来 K フレーム分 (a_t, …, a_{t+K}) を一度に出し、A が走らない間は B が最新の状態で毎フレーム補正する | 「全体の計算が重くて毎フレーム回せない」という動機に最も直接対応。K を変えれば B の価値を定量的に測れる | 実装量が大きく、A の出力が 8×(K+1) 次元になる。K=2〜3 から |
| C-3 B の入力追加 | 遅れなしで取れる速いセンサ (IMU の角速度・重力方向、脚の接地、同じ脚の他の 2 関節) を B に入れる | 今の B は自分の関節の値しか見ず、胴体の傾きに応じた補正 (バランス補正) ができない | 入力が増えると「軽い局所補正」から外れる。効果と計算量のトレードオフを見る |
| C-4 重み共有 | 1 つの MLP を 8 関節 (または左右の脚) で共有し、関節 ID の埋め込みを入力に足す | 1 つの重みが受けるデータが 8 倍になり、過学習しにくく学習が速い | 関節ごとの特性が ID 埋め込みで足りるかは要確認。共有なしと比較し、落ちるなら戻す |
| C-5 正則化 | PPO の損失に λ·\|Δ\|² を足す、または Δ に上限を付ける | B が A の仕事を肩代わりしない (A が主、B は補助)。Δ の RMS で B の寄与が測れる。実機での安全性 | 強すぎると B が何もしなくなる。λ・上限は小さい値から調整 |

### D. 実機寄りの発展

- **B をサーボの逆動特性補償器にする**: 実機のサーボ遅れ (約 23 ms) を、実機データで教師あり学習した B が打ち消す。A は sim で学習する。sim2real の話として構成が最も筋が通る。
- **履歴から応答特性を推定する (RMA 風)**: B が (a, q) の履歴から、サーボの応答や負荷を推定する。

## 4. 手を付ける順序の提案

| 順 | 項目 | 実装量 | 理由 |
|---|---|---|---|
| 1 | A-1, A-2, A-3 | 小 | 既存の実装で回せる。「B が効く条件があるか」の診断で、結果次第で以降の方針が変わる |
| 2 | B-4, B-3, C-5, C-4 | 小〜中 | `frozen` のコードや B の定義を少し変えるだけで試せる |
| 3 | B-1, C-3 | 中〜大 | 効果が出やすく貢献として書きやすい。A の結果 (外乱評価) があると、C-3 の効果を測りやすい |
| 4 | C-2 | 大 | 動機に最も合うが実装量が大きい。1 の結果を見てから判断 |
| 5 | D | 大 | 実機データが必要。実機への適用性は現状の結果からは言えない |
